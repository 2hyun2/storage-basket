# 수납바구니 인수인계

## 1. 제품 목표

집 안 물건이 어디에 있는지 텍스트로 기록하고 빠르게 검색한다. 위치는 `id`와 `parentId`로 연결되는 트리이며, 물건은 `locationId`로 위치를 참조한다.

텍스트 위치 데이터가 원본이다. 3D 기능은 원하는 사용자만 쓰는 선택 기능으로 추가하며, 부모 기준 로컬 좌표와 미터(m) 단위를 사용한다. 초기 3D 형상은 모두 직육면체로 제한한다.

## 2. 기술 스택

현재 적용:

- React 19 + Vite 8
- Tailwind CSS 4
- Zustand 5
- React Router, TanStack Query, Three.js, React Three Fiber, Drei 설치 완료
- ESLint

예정:

- Node.js + Express
- Supabase Auth + PostgreSQL
- Docker + Docker Compose
- 프론트 배포와 Express API 배포

## 3. 새 환경 실행 순서

```powershell
git clone https://github.com/2hyun2/storage-basket.git
cd storage-basket\front
npm ci
npm run dev
```

변경 후 확인:

```powershell
npm run lint
npm run build
```

`npm ci`는 `package-lock.json`에 기록된 버전대로 의존성을 재설치한다. `node_modules`는 Git으로 옮기지 않는다.

## 4. 현재 구현 완료 기능

- 반응형 상단바·사이드바·콘텐츠 레이아웃
- `id`/`parentId` 기반 재귀 위치 트리
- 위치 노드 펼치기·접기
- 선택한 위치와 모든 하위 위치의 물건 필터링
- 물건명·위치·카테고리·태그·메모 통합 검색
- 최근 수정·최근 등록·가나다·수량 기준 정렬
- 물건 카드와 상세 모달/모바일 바텀시트
- 물건 등록 폼과 클라이언트 유효성 검사
- 위치 등록 폼과 부모 위치 선택
- 등록·수정 시각 및 작업자 ID 데이터 구조
- Obsidian에서 `docs` 폴더 문서 확인

## 5. 현재 데이터 흐름

```text
data/ 더미 배열
    ↓
useInventory
    ├─ 물건·위치 브라우저 메모리 상태
    └─ 임시 생성 함수
    ↓
useVisibleItems
    ├─ 선택 위치 및 하위 위치 필터
    ├─ 검색 필터
    └─ 정렬
    ↓
App
    ├─ Header
    ├─ Sidebar → LocationTree → LocationTreeNode
    ├─ Content → ItemList → ItemCard
    └─ 상세·물건 등록·위치 등록 모달
```

화면 선택·검색어·정렬·모달 상태는 `useAppStore`가 관리하고, `useAppUi`가 App에서 필요한 상태만 묶어 제공한다.

## 6. 핵심 데이터 형태

위치:

```text
id, name, parentId,
createdAt, createdBy, updatedAt, updatedBy
```

물건:

```text
id, title, locationId, locationPath, quantity,
options { unit, category, tags, note },
createdAt, createdBy, updatedAt, updatedBy
```

현재 `locationPath`는 표시 편의를 위해 물건에도 저장한다. 위치 이름이나 부모가 바뀌는 기능을 구현할 때는 경로 동기화 정책을 다시 결정해야 한다.

## 7. 중요한 구현 원칙

- 서버 데이터 원본을 Zustand에 복제하지 않는다. 서버 연결 후 원본은 TanStack Query가 관리한다.
- Zustand에는 선택 ID, 검색어, 정렬, 모달 상태 같은 UI 상태만 둔다.
- 위치 경로 계산은 `utils/location.js`에 둔다.
- 필터·검색·정렬은 `useVisibleItems`에서 처리한다.
- `sort()`는 원본 배열을 변경하므로 복사본만 정렬한다.
- 사용자 입력은 React 일반 텍스트로 렌더링하고 `dangerouslySetInnerHTML`을 사용하지 않는다.
- 클라이언트 검증은 UX용이다. Express 연결 후 서버에서도 Zod 등으로 다시 검증한다.
- 이름 중복은 ID가 다르므로 허용한다. 동일 부모의 동일 이름 경고는 추후 선택 사항이다.

## 8. 현재 한계

- 위치와 물건 추가 결과는 새로고침하면 사라진다.
- 수정·삭제·물건 이동 기능이 없다.
- 위치 이름 또는 부모 변경 시 `locationPath` 갱신 기능이 없다.
- 회원가입·로그인·공유 코드·권한 검사가 없다.
- 백엔드와 DB가 없다.
- 모바일 위치 트리 접근 UI가 아직 없다.
- 3D 데이터와 화면은 아직 구현하지 않았다.

3. 모바일 위치 트리 드로어
4. Express 서버 생성과 상태 확인 API
5. Supabase/PostgreSQL 스키마 설계
6. TanStack Query로 더미 메모리 상태를 실제 API로 교체

8. 공유 코드와 비회원 참여 토큰

## 10. 서버 연결 후 목표 흐름

```text
React
→ TanStack Query
→ Express API
→ JWT 또는 익명 참여 토큰 검증
→ home 멤버 및 CRUD 권한 확인
→ Supabase PostgreSQL
```

회원 JWT는 로그인 사용자 식별에 사용한다. 비밀번호·이메일 변경처럼 민감한 계정 작업은 JWT만 믿지 않고 Supabase Auth의 재인증 흐름을 사용한다.
