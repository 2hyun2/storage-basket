# 협업 가이드

작성일: 2026-11-10 (한국 시간)

## 목적과 역할

우리집 공간록의 코드와 설계 문서를 정현·Codex·Claude가 이어서 관리한다. Obsidian은 같은 Markdown 파일을 읽고 편집하는 공간으로 사용한다.

| 참여자·도구 | 역할 |
| --- | --- |
| 정현 | 제품 방향, 우선순위, 필요한 의사결정 |
| Claude | 코딩 작업 담당: 설계·구현·코드 수정, 관련 기능 문서·결정 기록 갱신, 변경 이유와 미실행 검증 기록 |
| Codex | 검증 담당: Git 상태·diff 대조, lint·build·test 실행과 결과 기록, 실제 코드 기준 검토 및 차이점 보고 |
| Obsidian | 기능 명세, 결정 근거, 인수인계 열람·편집 |

역할은 [COLLAB-003](결정-기록.md)에 따른다. Codex는 검증 중 발견한 문제를 직접 고치지 않고 인수인계에 차이점으로 남기며, 수정은 Claude가 한다. 정현이 특정 작업에서 다르게 지정하면 그 지시를 따른다. 환경이 달라지면 역할을 갱신한다. 다른 AI의 설명도 실제 파일과 실행 결과로 확인한다. 외부 AI에 메시지를 전달하거나 도구 간 자동 동기화를 설정했다고 가정하지 않는다.

## 기준 자료

- 사용자의 현재 명시적 요청을 우선한다.
- 공통 작업 규칙은 앱 루트 `AGENTS.md`와 이 문서에 둔다. `CLAUDE.md`는 진입 안내만 유지한다.
- 실행 명령과 의존성은 `package.json`·lockfile, 현재 동작은 코드, DB 변경 정의는 `supabase/migrations/`를 확인한다.
- 의도한 기능 기준은 관련 최신 기능 문서와 결정 기록을 확인한다. 구현과 명세가 다르면 이를 숨기거나 어느 한쪽을 자동으로 정답 취급하지 말고 차이를 인수인계에 남긴다.
- `작업-현황-및-다음-계획.md`는 과거 기록이다. 최신 상태와 중복된 별도 현황 문서를 계속 만들지 않는다.
- 로컬 코드, 자동 검증, 실제 브라우저 확인, 운영 DB 적용은 서로 다른 확인이다. 수행하지 않은 것을 완료로 기록하지 않는다.

## 시작할 때

1. `AGENTS.md`, 이 문서, `인수인계.md`를 읽는다.
2. Codex는 앱 루트에서 `git status --short`와 관련 `git diff`를 확인한다. Claude는 인수인계에 남은 실행 결과를 참고하고, 새 Git 확인이 필요하면 Codex 확인 대기로 기록한다. 기존 변경을 덮어쓰거나 되돌리지 않는다.
3. 관련 코드·기능 문서를 읽고 작업 범위와 검증 방법을 정한다. Next.js 변경 전에는 `AGENTS.md`가 지정한 설치된 버전 문서를 확인한다.
4. 진행 중인 작업이 있다면 담당과 대상 파일을 확인한다. 작업 시작 시 인수인계의 현재 작업에 담당·대상 파일·진행 중 상태를 먼저 기록한다. 같은 파일을 여러 편집기·AI에서 동시에 저장하지 않는다. 이 표는 자동 잠금이 아니므로 다른 담당이 진행 중이면 인계가 확인된 뒤 해당 파일을 수정한다.

## 구현 원칙

- 현재 프로젝트는 Next.js App Router, React, TypeScript, Tailwind CSS, Supabase, TanStack Query, Zustand, Three.js 관련 라이브러리를 사용한다. 정확한 버전은 `package.json`과 lockfile을 확인한다.
- UI 수정은 기존 Tailwind 패턴과 `UI-디자인-기준.md`를 따른다. 새 라이브러리·전역 스타일·구조 변경은 필요성이 있을 때만 도입한다.
- 공간 단위는 정수 cm다. 사용자 좌표와 렌더러 좌표를 혼동하지 않는다. 상세 기준은 `공간-입력-수정-공통-규칙.md`를 따른다.
- Home 경계와 권한 검증, RLS, 서버 검증을 유지한다. 화면에서 숨기는 것으로 권한 검증을 대체하지 않는다.
- DB 변경은 새 migration으로 남긴다. 이미 적용된 migration을 다시 작성하지 않는다. 여러 데이터의 일괄 변경은 기존 트랜잭션 방식을 따른다.
- `.env.local`, 토큰, 비밀번호, 실제 사용자 개인정보는 문서·커밋·작업 로그에 넣지 않는다. 설정 설명에는 `.env.example`의 변수명과 자리표시자를 사용한다.
- 배포, 운영 DB 실행, 커밋·push는 해당 요청에서 허용한 범위에 따라 진행한다. 문서 작성 요청을 배포 요청으로 확대하지 않는다.

## 검증

명령은 Codex가 앱 루트에서 실행하고, 명령·종료 코드·핵심 출력·미실행 이유를 인수인계에 남긴다. 민감한 값은 기록하지 않는다. Claude는 실행하지 못한 검증을 Codex 확인 대기로 표시하며, 검증 완료로 간주하지 않는다. 아래는 사용 가능한 명령이며, 현재 세션에서 통과했다는 뜻은 아니다.

| 변경 | 검증 |
| --- | --- |
| Markdown만 변경 | 상대 링크, 경로, 내용 충돌, Git diff 확인 |
| 코드 변경 | `npm.cmd run lint`, `npm.cmd run build` |
| 데이터·권한·공간 계산 등 동작 변경 | 위 검사와 `npm.cmd test`, 필요하면 관련 수동 QA |
| UI·3D 변경 | 관련 브라우저 화면과 모바일·데스크톱 조작 확인; 미확인 시 명시 |
| DB 변경 | 로컬 검증 결과와 운영 적용 여부를 구분하여 기록 |

테스트는 변경 위험에 맞춰 추가한다. 실행 실패와 실행하지 못한 검증은 이유와 함께 남긴다. 인증 정보가 필요한 운영 검증을 로컬 테스트 결과로 대신하지 않는다.

## 작업을 넘길 때

- `인수인계.md`의 현재 작업을 갱신한다. 변경 파일, 실제 실행한 명령과 결과, 미확인 사항, 다음 행동을 짧게 쓴다.
- Claude는 수정 파일별 변경 이유와 미실행 검증을 남긴다. Codex는 인계받은 뒤 실제 diff와 기록을 대조한다. Git 미추적 새 파일은 diff에 나오지 않으므로 파일 내용도 직접 확인한다.
- Claude가 작성한 코드도 Codex가 검토한다. 공간 좌표·정수 cm·축 변환, Home 경계·RLS·권한, migration·트랜잭션 변경은 관련 명세와 실제 코드로 확인하고 필요한 검증을 실행한다. Claude도 Codex 변경을 실제 파일 기준으로 검토한다.
- 새 제품·구조 결정을 했다면 `결정-기록.md`와 해당 기능 문서를 함께 갱신한다. 검토 중인 제안은 확정 결정에 넣지 않는다.
- 담당은 실제 작업 주체만 기입한다. 대화에서 요청하지 않은 다른 AI에게 작업을 배정하거나 완료 처리하지 않는다.
- 다른 도구에서 이어갈 때는 같은 파일을 읽게 한다. 복사본을 별도의 원본으로 운영하지 않는다.

## Obsidian 사용

- `storage-basket/`을 보관함으로 열면 코드 저장소와 같은 `docs/`를 읽는다. 상위 작업 폴더를 열어도 상대 링크는 사용할 수 있다.
- `docs/README.md`를 목차로 사용한다. 특별한 플러그인 없이 읽을 수 있는 Markdown과 상대 링크를 유지한다.
- `node_modules`, `.next`, `.git`은 문서 탐색·검색에서 제외하도록 Obsidian에서 설정하는 것을 권장한다. 이번 작업에서 앱 설정을 자동 변경하지는 않았다.
- 개인 테마·창 배치 등 `.obsidian/` 설정은 협업 규칙의 원본으로 삼지 않는다. 공유 필요 여부를 정한 뒤 Git 추적 정책을 정한다.
- Git 또는 별도 파일 동기화를 선택했다면 저장 충돌을 확인한다. 동기화 도구는 이번 문서 생성으로 설치·연결되지 않는다.
