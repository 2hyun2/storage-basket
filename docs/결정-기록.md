# 결정 기록

제품·구조·협업 방식의 확정 사항과 이유를 기록한다. 제안은 확정 기록과 구분하고, 변경 시 이전 결정을 지우지 말고 대체한 기록을 연결한다.

## COLLAB-001 — 공통 Markdown으로 협업

- 날짜: 2026-11-10 (한국 시간)
- 상태: 적용 — 이번 문서 구성 기준. 후속 사용자 요청으로 변경 가능.
- 배경: 정현이 Codex·Claude·Obsidian이 협업할 지침과 Markdown 파일 생성을 요청했다.
- 결정: 앱 `AGENTS.md`와 `docs/협업-가이드.md`에 공통 작업 규칙을 두고, `CLAUDE.md`는 해당 문서로 안내한다. Obsidian도 같은 `docs/`를 열람·편집한다.
- 이유: AI별 규칙 복제와 서로 다른 문서 복사본에서 생기는 불일치를 줄인다.
- 영향: 현재 진행 상태는 `인수인계.md`, 제품·구조 결정은 이 파일, 기능 명세는 관련 기능 문서에서 관리한다.
- 범위 밖: AI 간 자동 메시지 전달, Obsidian 설정 변경, 자동 동기화, 커밋·push·배포는 이번 요청으로 실행하지 않는다.

## COLLAB-002 — 명령 실행과 상호 검토 역할 분담

- 날짜: 2026-11-10 (한국 시간)
- 상태: 적용 — 사용자가 전달한 Claude 협업 요청 반영.
- 배경: 현재 Claude 환경에서는 파일 읽기·쓰기만 가능하며 Git·lint·build·test를 실행할 수 없다.
- 결정: Codex가 명령 실행과 결과 기록을 담당한다. Claude는 변경 파일·이유·미실행 검증을 인수인계에 남긴다. Codex는 기록과 실제 변경을 대조하고, 특히 공간 좌표·RLS·권한·migration을 검토한다.
- 동시 편집: 시작 전에 현재 작업 표에 담당과 대상 파일을 기록한다. 다른 담당의 진행 중 파일은 인계 확인 후 수정한다. 이 기록은 자동 파일 잠금 기능이 아니다.
- 영향: 양쪽 모두 실제 파일 기준으로 상호 검토하며, 실행하지 않은 검증은 완료로 표시하지 않는다. Claude 실행 환경이 달라지면 역할을 갱신한다.
- 관련 문서: [협업 가이드](협업-가이드.md), [인수인계](인수인계.md).
- 이전 결정과 관계: COLLAB-001을 유지하며 실행 역할을 구체화한다.

## UI-001 — 포인트 색 클래스는 `violet-*` 유지

- 날짜: 2026-11-10 (한국 시간)
- 상태: 확정 — 정현 결정.
- 배경: 디자인 기준은 포인트 색을 파랑으로 정했으나, 코드는 `violet-*` 클래스를 쓰고 `app/globals.css`가 이를 파랑 값으로 재정의한다. Claude가 읽은 일부 UI 파일에서는 `blue-*`가 0회였고, 이후 Codex 저장소 전체 검색에서 기존 코드 4개 파일·11개 토큰이 확인되었다.
- 결정: 포인트 색은 계속 `violet-*` 클래스로 작성한다. 새 코드에 `blue-*`를 쓰지 않는다. 기존 `blue-*` 11개 토큰은 2026-11-10 정현 요청으로 같은 숫자의 `violet-*`로 모두 교체했다. 무채색 `slate-*`, 오류 `rose-*`, 물건 보조 `sky-*`를 표준으로 함께 기록한다.
- 이유: 기존 코드를 일괄 변경하지 않고, AI·사람이 같은 클래스를 쓰도록 이름을 고정한다.
- 영향과 고려한 대안: `blue-*`로 전면 교체하는 안은 변경 범위가 커서 채택하지 않았다. 클래스 이름과 실제 색이 다르다는 점은 문서로 보완한다.
- 관련 문서·작업: [UI 디자인 기준](UI-디자인-기준.md)의 색상 클래스.
- 대체한 결정 또는 후속 결정: 없음.

## UI-002 — 물건 등록 전에 보관 공간 안내

- 날짜: 2026-11-10 (한국 시간)
- 상태: 적용 — 정현 요청 반영.
- 배경: 새 계정에 공간이 없어도 물건 등록 화면을 열 수 있고, 폼 하단의 작은 안내만으로는 다음 행동을 알기 어렵다.
- 결정: 공간이 0개이면 물건 등록 진입과 폼을 큰 공간 우선 안내 및 공간 등록 버튼으로 대체한다. 등록 선택 화면, 물건 목록 및 다이얼로그에 공통 안내를 사용한다. 직접 URL 진입에도 적용한다.
- 이유: 보관 공간을 먼저 만든 뒤 물건을 기록하는 순서를 명확하게 안내한다.
- 영향: 조회 중·조회 실패는 공간 없음과 별도로 표시한다. 기존 공간이 있는 계정의 물건 등록과 공간 입력·집 크기 설정 흐름은 유지한다. DB·권한·의존성 변경 없음.
- 관련 문서: [UI 디자인 기준](UI-디자인-기준.md).
- 후속: 재조회 실패 시 기존 공간 데이터가 있으면 오류 화면으로 바꾸지 않도록 수정했다(2026-11-10, Claude). "조회 실패" 안내는 공간 데이터가 없을 때만 표시한다.

## COLLAB-003 — Claude는 코딩, Codex는 검증

- 날짜: 2026-11-10 (한국 시간)
- 상태: 확정 — 정현 결정.
- 배경: COLLAB-002 이후 Codex가 구현(UI-002)과 검증을 함께 맡은 사례가 생겼고, 같은 파일을 두 AI가 이어서 고치며 인수인계 동시 저장도 발생했다.
- 결정: 코드 작성·수정은 Claude가 담당한다. Codex는 검증(Git diff 대조, lint·build·test, 실제 코드 기준 검토)을 담당하며, 발견한 문제는 직접 고치지 않고 인수인계에 차이점으로 남긴다.
- 이유: 작성자와 검증자를 분리해 서로 덮어쓰기를 줄이고, 검증이 작성자 본인의 확인에 머물지 않게 한다.
- 영향과 고려한 대안: 요청마다 담당을 정하던 방식보다 고정 분담을 우선한다. 정현이 특정 작업에서 다르게 지정하면 그 지시를 따른다.
- 관련 문서·작업: [협업 가이드](협업-가이드.md)의 역할 표, [인수인계](인수인계.md).
- 대체한 결정 또는 후속 결정: COLLAB-002의 역할 부분을 구체화한다. 명령 실행은 계속 Codex가 맡는다.

## COMM-001 — 기본 공동체 이름은 표시 이름 변경을 따라간다

- 날짜: 2026-11-10 (한국 시간)
- 상태: 확정 — 정현 결정.
- 배경: 가입 트리거가 공동체 이름을 `{표시 이름}의 수납바구니`로 한 번만 만든다. Google 가입은 이름을 `full_name`으로 넘겨 트리거가 이메일 아이디를 쓰므로, 표시 이름을 바꿔도 공동체 이름에 이메일 아이디가 남았다.
- 결정: 표시 이름을 저장할 때, 내가 대표인 공동체 중 이름이 기본 이름 그대로(`{직전 표시 이름}의 수납바구니` 또는 `{이메일 아이디}의 수납바구니`)인 것만 `{새 표시 이름}의 수납바구니`로 바꾼다. 직접 지은 이름과 대표가 아닌 공동체는 바꾸지 않는다.
- 이유: 사용자가 정하지 않은 자동 이름에 이메일 아이디가 노출되는 것을 막고, 직접 정한 이름은 보존한다.
- 영향과 고려한 대안: 대안 "직접 수정만"은 채택하지 않았다. 공동체 이름 변경 실패는 표시 이름 저장 실패로 처리하지 않고 안내만 한다. 가입 트리거가 `full_name`을 읽도록 고치는 마이그레이션은 미정.
- 관련 문서·작업: `components/display-name-form.tsx`, `lib/community/default-home-name.ts`, [인수인계](인수인계.md).
- 대체한 결정 또는 후속 결정: 없음.
