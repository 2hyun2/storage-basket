# 우리집 공간록 QA 점검 체크리스트

> 마지막 점검: 2026-10-30  
> 목적: 자동으로 확인 가능한 코드·빌드 검증과 실제 사용자가 눌러 봐야 하는 흐름을 분리한다.

## 이번 최종 QA 결과

- 공개 경로 `/`, `/login`, `/signup`은 로컬에서 `200` 응답을 확인했다.
- 보호 경로 `/app`, `/app/items`, `/app/archive`, `/app/community`, `/app/space`, `/app/space/create`은 로그인 화면으로 이동하며 원래 주소를 보존한다.
- 물건 상세 주소도 `/app/items?detail=…` 그대로 로그인 후 복귀할 수 있도록 확인했다.
- TypeScript 검사와 ESLint는 통과했고, 변경 파일의 공백·충돌 검사도 통과했다.
- 반응형 코드는 320px 모바일부터 넓은 화면까지를 기준으로 검토했다. 헤더는 햄버거 메뉴로 전환되고, 목록·등록/상세 창·푸터는 줄바꿈 또는 세로 스크롤을 허용한다.
- 이 작업 환경은 브라우저에서 `localhost`를 직접 열어 실제 클릭·드래그를 시연하는 권한을 제공하지 않는다. 따라서 아래 **최종 공동 QA**의 실제 조작 항목은 사용자 브라우저에서 확인한다.

## 1. Codex가 완료한 점검

- [x] TypeScript 검사 통과 (`tsc --noEmit`)
- [x] ESLint 검사 통과 (오류·경고 없음)
- [x] Next.js 프로덕션 컴파일 통과
- [ ] 이 PC의 `next build` 최종 TypeScript 워커는 운영체제 권한 오류(`spawn EPERM`)로 실행되지 않았다. 별도 `tsc --noEmit`은 통과했으며, 최종 배포 전 Vercel 빌드 결과를 확인한다.
- [x] 주요 경로 생성 확인
  - `/`
  - `/login`, `/signup`, `/auth/callback`
  - `/app`, `/app/items`, `/app/items/trash`, `/app/archive`
  - `/app/community`, `/app/my`
  - `/app/space`, `/app/space/create`, `/app/space/[locationId]`
  - `/app/space/[locationId]/structure/create`
- [x] 비로그인 상태의 보호 경로 확인
  - `/app` → `/login?next=%2Fapp`
  - `/app/items?create=1` → 원래 주소를 포함한 로그인 화면
  - `/app/archive` → 원래 주소를 포함한 로그인 화면
- [x] 드래그 배치 공통 캔버스 점검
  - 공간·벽·창문이 같은 `PlanPlacementCanvas`를 사용한다.
  - 드래그 시작/끝 좌표는 10cm 격자에 맞춘다.
  - 숫자 입력으로는 1cm 단위 조정이 유지된다.
- [x] 물건·공간 삭제 흐름 코드 점검
  - 물건은 휴지통으로 보내고 복원할 수 있다.
  - 공간 삭제 때 물건을 다른 공간으로 일괄 이동하거나 휴지통으로 보낼 수 있다.
  - 물건 이동·휴지통·복원은 DB RPC에서 처리하도록 구성되어 있다.
- [x] 변경 기록 구조 점검
  - 물건, 공간, 3D 배치, 벽·창문, 장면 크기 변경을 `activity_events`에 남기는 트리거를 준비했다.
  - 기록은 변경 당시 이름·경로·치수 스냅샷을 보관한다.
  - `/app/archive`, 물건별 기록, 공간별 기록 화면 연결을 확인했다.

## 3. 사용자가 직접 확인할 QA

실제 데이터가 지워지지 않도록, 가능하면 별도의 테스트 공동체에서 진행한다.

### A. 가입과 로그인

- [ ] 회원가입 후 인증 메일 링크를 열면 `/app`으로 들어간다.
- [ ] 비밀번호가 틀리면 이메일은 남고 비밀번호만 비워진다.
- [ ] `이메일 기억`을 선택했을 때만 다음 로그인 화면에 이메일이 남는다.
- [ ] `로그인 상태 유지`를 선택하지 않았을 때 브라우저를 완전히 종료·재시작하면 자동 로그인이 유지되지 않는다.
- [ ] 선택했을 때는 `/` 대신 `/app`으로 바로 이동한다.

### B. 공동체

- [ ] 공동체를 만들고 이름·대표 표시가 자연스럽게 보인다.
- [ ] 초대 링크를 열면 회원가입 화면에 코드가 채워지고, `코드 확인` 뒤 공동체 이름·대표가 보인다.
- [ ] 공동체 이름·대표를 확인했다는 체크를 해야 가입 버튼이 활성화된다.
- [ ] 초대 코드/링크로 다른 테스트 계정이 참여한다.
- [ ] 이미 가입한 계정도 공동체 화면에서 초대 코드 → 공동체 이름·대표 확인 → 참여할 수 있다.
- [ ] 여러 공동체에 참여한 계정이 `내 공동체`에서 표시할 공동체를 바꿀 수 있다.
- [ ] 두 계정에서 같은 공간·물건 변경 내용이 새로고침 뒤 동일하게 보인다.
- [ ] 권한 없는 계정이 다른 공동체 주소를 직접 열어도 데이터가 보이지 않는다.

### C. 공간과 3D 배치

- [ ] 우리 집의 가로·세로를 설정하기 전에는 공간 등록과 3D 배치가 막힌다.
- [ ] 텍스트 공간을 등록하고, 같은 화면에서 `3D 그리기`로 전환할 수 있다.
- [ ] 드래그 시작·끝이 10cm 단위로 맞는다.
- [ ] 숫자로 1cm 값을 넣으면 정확히 저장된다.
- [ ] 부모 바깥, 형제 공간·벽·창문과 겹치는 배치는 저장되지 않는다.
- [ ] 공간 수정 후 평면 격자, 상세 화면, 홈 미리보기가 같은 치수를 보여 준다.
- [ ] 공간 상세의 `공간 이름 수정`에서 이름을 바꾼 뒤, 텍스트 트리·3D 이름표·상세 제목이 함께 바뀐다.
- [ ] 벽·창문 생성·수정 화면에서 기존 공간과 구조물이 함께 보인다.
- [ ] 모바일에서 드래그, 숫자 입력, 저장 버튼이 화면 밖으로 밀리지 않는다.

### D. 물건과 검색

- [ ] 물건을 이름·보관 공간·수량·분류·메모로 등록한다.
- [ ] 물건에는 좌표 입력이 없고 선택한 공간에만 연결된다.
- [ ] 홈 검색과 `/app/items` 검색에서 이름·분류·보관 경로로 찾을 수 있다.
- [ ] 검색 결과의 보라색 `보관 위치` 경로를 누르면 실제 공간 상세로 이동한다.
- [ ] 물건 이름 또는 `상세`를 누르면 수량·분류·메모·현재 위치가 한 화면에 보인다.
- [ ] 물건 상세의 최근 변경 기록에서 이전 위치 → 새 위치가 보이고, `전체 기록 보기`는 해당 물건 기록만 연다.
- [ ] 물건을 다른 공간으로 옮기면 새 경로가 모든 화면에 반영된다.
- [ ] 물건 수정·휴지통·복원이 동작한다.
- [ ] 공간 삭제 시 내부 물건을 다른 공간으로 옮기거나 휴지통으로 보낼 수 있다.

### E. 변경 기록

> 2번 SQL 적용 후 확인한다.

- [ ] 물건을 등록하고 전체 기록에 `등록`이 보인다.
- [ ] 물건을 옮기고 이전 경로 → 새 경로가 기록된다.
- [ ] 물건을 휴지통으로 보낸 뒤 복원하고 각각 기록된다.
- [ ] 공간·3D 자리·벽·창문을 바꾼 뒤 기록이 남는다.
- [ ] 물건 상세의 기록 버튼은 해당 물건 기록만, 공간 상세의 기록 버튼은 해당 공간 기록만 보여 준다.
- [ ] 나중에 공간 이름을 바꿔도 이전 기록은 당시 이름과 경로를 유지한다.

### F. 배포와 반응형

- [ ] Vercel 배포 주소에서 회원가입·로그인·공간·물건·기록 흐름이 로컬과 동일하다.
- [ ] PC, 태블릿, 모바일 폭에서 헤더 메뉴·등록 창·3D 화면·목록이 가로 스크롤 없이 보인다.
- [ ] 새로고침과 다른 기기에서 DB 데이터가 같은 모습으로 나타난다.

## 4. 최종 공동 QA 순서

같은 공동체를 쓰는 테스트 계정 A·B와, 아래 세 화면 크기만 준비하면 된다.

```text
모바일 360 × 800
태블릿 768 × 1024
PC 1440 × 900
```

1. **A 계정 · 모바일**: 햄버거 메뉴를 열고 모든 메뉴를 한 번씩 이동한다. 메뉴가 링크를 누른 뒤 닫히는지, 가로 스크롤이 생기지 않는지 본다.
2. **A 계정 · 물건 찾기**: 물건 하나를 검색 → 상세 → 현재 위치 → 실제 공간 이동 → 뒤로가기 → 전체 기록 보기를 차례로 확인한다.
3. **A 계정 · 공간**: 텍스트 공간 하나를 등록하고 3D 자리 정하기로 전환한다. 드래그는 10cm, 숫자 수정은 1cm인지 확인한다. 일부러 겹치게 배치해 저장이 막히는지도 확인한다.
4. **A 계정 · 구조물**: 벽 또는 창문 하나를 추가·수정·삭제한다. 공간과 구조물이 서로 겹치지 않으며 기록이 남는지 확인한다.
5. **B 계정 · 공동체**: A의 초대 코드로 참여한다. A가 물건 위치를 바꾼 뒤 B에서 새로고침하면 위치·기록이 동일한지 확인한다.
6. **PC·태블릿**: 1~2번 화면을 다시 열어 검색 카드, 상세 창, 3D 캔버스, 푸터가 화면 폭에 맞춰 배치되는지 확인한다.
