# 공동체 관리 검증

적용 SQL: `202610300004_community_member_management.sql`.

## 처리 규칙

- 초대 코드는 `homes.invite_code` 하나만 사용한다. 재발급은 멤버 소속과 무관하다.
- 일반 멤버는 소속과 기록을 유지한다. 기존 초대 코드·링크는 재발급 이후 참여에 사용할 수 없다.
- 강퇴는 대표 전용 RPC로 소속만 삭제한다. 대표·본인 강퇴는 차단한다.
- 멤버 참여·강퇴·멤버 정보 변경 이력은 모두 아카이브에 남기지 않는다. 기존 공간·물건·활동 내역, Auth 계정은 유지한다.
- 강퇴된 멤버의 현재 공동체가 대상과 같으면 다른 소속으로 변경하고, 소속이 없으면 null로 바꾼다.
- DB 권한은 멤버십 삭제 직후 RLS로 제한된다. 이미 기기에 전달된 데이터는 회수할 수 없다. 화면 데이터는 60초 후 오래된 것으로 판단하며, 창 포커스 복귀·화면 재진입·명시적 새로고침 때 갱신한다. 30초 전체 조회는 제거했다.
- 초대 코드가 유효하면 강퇴된 계정도 재참여할 수 있다. 영구 차단 목록은 만들지 않는다.

## SQL 적용 후 실제 두 계정에서 확인할 항목

| 시나리오 | 기대 결과 |
| --- | --- |
| 대표가 초대 코드 재발급 | 새 코드 표시, 기존 구성원 수·공간·물건 유지 |
| 일반 구성원이 탭 재진입 | 기존 소속 유지 |
| 이전 코드로 가입·참여 | 만료/유효하지 않음 표시 |
| 새 코드로 참여 | 공동체 확인 후 참여 성공 |
| 대표가 일반 구성원 강퇴 | 목록에서 제거, 공동체 공유 데이터 유지 |
| 일반 멤버의 관리 RPC 직접 호출 | DB에서 거부 |
| 대표가 본인·다른 대표를 강퇴 시도 | DB에서 거부 |
| 이미 강퇴된 멤버 반복 요청 | 오류 표시, 다른 멤버에 영향 없음 |
| 강퇴된 계정의 데이터 조회·수정 | 대상 공동체 RLS 거부 |
| 강퇴된 계정에 다른 소속 있음 | 다른 소속 공동체로 전환 |
| 강퇴된 계정에 다른 소속 없음 | 공동체 화면에서 새 초대 코드 확인·참여 가능 |
| 활동 기록 조회 | 기존 물건·공간 기록 유지, 강퇴 이벤트 없음 |

실제 DB RPC 동작은 SQL 적용 및 두 계정 테스트 전까지 미검증이다.
